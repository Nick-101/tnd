## 1. 한눈에

- 규칙 텍스트 100개(건물 95채, 특성 5개)를 문형 열네 개로 쓴다. 평균 24자, 가장 긴 것은 휴게소 53자다.
- **문장형이고 발라트로의 꼴이다.** 수치가 결과인 줄은 부호 붙은 숫자로 끝내고, 그 밖의 줄은 합니다체다.
- **부호는 둘이다.** +는 더하고 ×는 곱한다. %는 쓰지 않는다. 한 매장에 걸린 ×는 자라는 것까지 모두 곱한다.
- **돈을 가리키는 말은 셋이다.** 요금(매장에 적힌 값), 매출(한 번 이용할 때 들어오는 돈), 자금(플레이어가 가진 돈).
- **가게와 손님에 대한 말은 현실의 말로, 판을 굴리는 말은 장르의 말로 쓴다.**

- 매장을 세는 말은 "곳"이다("매장 1곳당"). 건물을 세는 말은 "채"다.

## 3. 문체와 표기의 규칙

1. **결과가 수치 하나인 줄은 부호 붙은 숫자로 끝낸다.** 동사를 붙이지 않는다. "허기 +2.", "모든 [카페]는 매출 ×1.5."
2. **수치가 아닌 일은 합니다체 문장으로 쓴다.** 지나침, 소모, 한 번 더 이용, 효과의 적용, 바퀴 수가 그렇다.
3. **조사를 생략하지 않는다.** 대상에는 "은/는", 범위에는 "의", 조건에는 "~면", 시점에는 "~할 때"와 "~마다"를 쓴다. 다만 "요금", "매출", "만족도"와 부호 사이, "1당"의 앞뒤에는 조사를 넣지 않는다.
4. **상태 키워드는 기본형을 지킨다.** "만취 상태", "포만 상태".
5. **누가 하는지 헷갈릴 줄에는 주어를 적는다.** "드워프가 모든 [운동]을 한 번 더 이용합니다."

표지.

| 표지 | 쓰는 곳 |
|---|---|
| + | 더하기에만. 스택, 요금, 만족도, 매출 배율이 늘어나는 양 |
| × | 곱에만. 매출에 걸리는 곱과 지금의 배율 |
| ★ | 업그레이드 단계에만 |
| 대신 | 대체에만 |
| ~당 | 비례와 변환에만 |
| (지금 …) | 자라는 값의 지금 값에만. 화면이 숫자를 채운다 |
| [업종] | 그 업종의 매장. 아이콘으로 그린다 |

기본값(쓰지 않는다).

| 칸 | 기본값 |
|---|---|
| 시점 | 드워프가 이 매장을 이용할 때 |
| 대상 (매장의 효과) | 이용한 드워프 |
| 지속 (스택) | 그 바퀴가 끝날 때까지 |
| 처리 순서 | 지나칠지 확인, 스택을 읽는다, 매출이 들어온다, 소모한다, 스택을 준다. 문장도 이 순서다 |

지원 건물의 대상은 기본값을 두지 않고 "매장"이라고 적는다(v2에서는 "건물"로 줄여 썼다).

## 5. 용어 사전

### 5.1 가게와 손님의 말 (안내가 가르친다)

| 낱말 | 정의 (툴팁) |
|---|---|
| 매장 | 드워프가 이용하는 건물입니다 |
| 지원 건물 | 드워프가 지나가고 다른 건물을 돕는 건물입니다 |
| 업종 | 매장이 하는 장사의 갈래입니다. 운동, 식당, 카페, 술집, 오락, 공연, 쇼핑, 휴식이 있습니다. 매장 하나에 업종이 하나나 둘입니다 |
| 요금 | 매장에 적힌 값입니다. 요금에 붙는 +는 모두 더합니다 |
| 매출 | 드워프가 매장을 한 번 이용할 때 들어오는 돈입니다. 요금에 그 매장에 걸린 ×를 모두 곱한 값입니다. 소수는 버립니다 |
| 자금 | 지금 가진 돈입니다. 웨이브가 끝날 때 자금이 목표 이상이어야 합니다 |
| 이용 | 드워프가 매장에 들러 돈을 내는 것입니다 |
| 취향 | 드워프마다 좋아하는 업종이 둘, 싫어하는 업종이 하나 있습니다 |
| 만족도 | 좋아하는 업종의 매장을 이용하면 1 오르고 싫어하는 업종이면 1 내립니다. 추가 바퀴를 도는 데 씁니다 |
| 스택 | 드워프가 돌면서 쌓는 표식입니다. 바퀴가 끝나면 사라집니다 |
| 허기 / 포만감 | 한 눈금의 양 끝입니다. 하나가 오르면 다른 하나가 그만큼 내립니다 |
| 취기 | 술집이 주는 스택입니다 |
| 흥 | 공연이 주는 스택입니다 |
| 피로 | 매장을 이용할 때마다 1 오르는 스택입니다. [휴식]은 피로를 주지 않습니다 |
| 바퀴 | 보드를 한 번 도는 것입니다. 드워프는 기본으로 2바퀴를 돕니다 |
| 특성 | 몇몇 드워프가 가진 배지입니다 |

### 5.2 키워드 (툴팁이 뜬다)

| 키워드 | 갈래 | 정의 (툴팁) | 쓰는 곳 |
|---|---|---|---|
| 만취 상태 | 상태 | 취기가 3 이상인 상태입니다 | 5채 |
| 포만 상태 | 상태 | 포만감이 3 이상인 상태입니다 | 10채 |
| 지나칩니다 | 속성 | 드워프가 이 매장을 이용하지 않고 지나갑니다. 매출도 스택도 생기지 않습니다 | 13채 |
| 소모합니다 | 행동 | 그 스택을 0으로 만듭니다. 소모한 수만큼 효과를 냅니다 | 4채 |
| 한 번 더 이용합니다 | 행동 | 드워프가 그 매장을 이어서 다시 이용합니다. 매출이 다시 들어오고 스택과 만족도도 다시 받습니다. [휴식]이 피로를 만족도로 바꾸는 것은 한 번만 합니다 | 7채 |
| 추가 바퀴 | 일반 | 기본 바퀴를 다 돈 뒤 만족도를 내고 도는 바퀴입니다. 필요한 만족도는 3, 6, 12, 24로 오릅니다. 추가 바퀴로 자란 요금과 매출 배율은 이번 웨이브가 끝나면 처음으로 돌아갑니다 | 4채 |
| 매출 배율 | 일반 | 그 건물이 매출에 거는 ×의 크기입니다. 1에서 시작합니다 | 2채 |
| ★ | 일반 | 업그레이드 한 단계입니다. ★ 하나마다 그 매장은 매출 ×2. 세 개까지 올립니다 | 3채 |
| 요금이 가장 높은 매장 | 일반 | 지금 요금이 가장 높은 매장 한 곳입니다. 같으면 입구에서 가까운 매장입니다. 추가 바퀴로 자란 요금은 치지 않습니다 | 7채 |

"한 번 더 이용합니다"의 마지막 문장(휴식은 한 번만 바꾼다)은 시뮬레이터가 그렇게 돌았다는 것이고 Claude가 채운 것이다.

### 5.3 판을 굴리는 말

스테이지, 웨이브, 정비, 보드, 칸, 입구, 덱, 후보, 새로고침, 잠금, 철거, 건설, 업그레이드, 목표, 비용, 등급(일반, 고급, 희귀). 장르에서 익은 말을 쓴다. 정의는 처음 하는 사람을 위한 안내를 쓸 때 붙인다.

| 낸 돈, 번 돈, 수입 | 매출 |
| 가진 돈 | 자금 |
| 장사 건물, 가게 | 매장 |
| 종류 | 업종 |
| 허기짐, 취함, 피곤함 | 허기, 취기, 피로 |

## 6. 글 대신 화면이 맡을 것

제작 요청서에 넣는다.

| 무엇을 | 어떻게 |
|---|---|
| 지원 건물이 닿는 칸 | 지원 건물을 고르거나 그 위에 올리면 닿는 칸이 밝혀진다. "양옆 1칸", "양옆 2칸", "이전 칸"을 눈으로 본다 |
| 이전 칸의 방향 | 회전문에서 이전 칸으로 화살표가 그려진다 |
| 요금이 가장 높은 매장 | 그 매장에 표시가 붙는다. 건물을 짓거나 옮기면 바로 옮겨 간다 |
| ★이 가장 많은 매장 | 위와 같다 |
| 지금의 요금과 배율 | 매장마다 지금 요금과 걸린 ×를 숫자로 보여 준다. 다른 건물 때문에 바뀐 숫자는 색을 달리한다 |
| 지나침 | 드워프가 지나칠 때 매장 위에 까닭이 뜬다 |
| 덱의 취향 | 문장이 아니라 라벨과 아이콘이다. "인기 [운동][공연] · 비인기 [술집]" |
| 자라는 값의 지금 값 | 성장 지원 네 채의 문구 끝에 "(지금 +3)", "(지금 ×2.5)"가 붙고 추가 바퀴마다 바뀐다. 흐린 색으로 적는다 |
| 부호의 색 | 요금에 붙는 "+N"과 매출에 붙는 "×N"에 다른 색을 준다. 스택에 붙는 "+N"은 그 스택의 색이다 |
| 업그레이드 단계 | 매장 이름 옆에 ★을 단계만큼 그린다 |

## 7. 규칙 텍스트

### 7.1 문형 열네 개

| 꼴 | 문형 | 예 |
|---|---|---|
| 지나침 | [상태] 상태의 드워프는 지나칩니다. | 만취 상태의 드워프는 지나칩니다. |
| 준다 | [스택] +N. | 허기 +2. |
| 읽는다 | [스택] 1당 요금 +N. | 허기 1당 요금 +4. |
| 소모하고 읽는다 | [스택]을 모두 소모합니다. 소모한 [스택] 1당 요금 +N. | 흥을 모두 소모합니다. 소모한 흥 1당 요금 +8. |
| 문턱 | [조건]면 매출 ×N. | 만취 상태면 매출 ×2. |
| 단골 | [스택] +N. [업종]을 좋아하는 드워프는 대신 +M. | 허기 +1. [운동]을 좋아하는 드워프는 대신 +3. |
| 만족도로 바꾼다 | [스택] N당 만족도 +1. | 피로 4당 만족도 +1. |
| 지원: 더하기 | [범위]의 [대상]은 요금 +N. | 양옆 2칸의 [식당]은 요금 +12. |
| 지원: 곱하기 | [범위]의 [대상]은 매출 ×N. | 모든 [카페]는 매출 ×1.5. |
| 지원: 다시 | 드워프가 [범위]의 [대상]을 한 번 더 이용합니다. | 드워프가 양옆 1칸의 [운동]을 한 번 더 이용합니다. |
| 지원: 자람 | 추가 바퀴마다 [범위]의 [대상]은 요금 +N. (지금 +v) / 매출 배율 +N. (지금 ×v) | 추가 바퀴마다 양옆 1칸의 매장은 매출 배율 +0.5. (지금 ×1) |
| 지원: 조건부 | [조건]면 [대상]은 매출 ×N. | 보드의 업종이 6가지 이상이면 모든 매장은 매출 ×1.5. |
| 지원: 비례 | [세는 것] 1당 [대상]은 요금 +N. | 보드의 ★ 1개당 모든 매장은 요금 +1. |
| 특성 | 바퀴를 시작할 때 [스택] +N. | 바퀴를 시작할 때 허기 +2. |

문형을 벗어난 문장이 여섯이다. 2호점("드워프가 이 칸에서도 요금이 가장 높은 매장을 이용합니다."), 발전소("양옆 1칸에 있는 지원 건물의 효과를 한 번 더 적용합니다."), 온천("피로가 6 이상이면 만족도 +3."), 안락의자 공장과 대형 의자 공장("[휴식]이 주는 만족도 ×N."), 느긋함("기본으로 3바퀴를 돕니다.").

업종 아이콘 뒤의 조사는 업종마다 고정이다. 문자열이 업종마다 따로 있어서 그렇게 할 수 있다.

## 9. 14개 언어를 생각해 지금 정해 둘 것

1. **문자열 하나가 문장 하나다.** 건물의 문구는 효과마다 문자열이 하나씩이고, 화면이 순서대로 이어 붙인다.
2. **변수에는 숫자만 들어간다.** 업종 이름을 문장에 끼우지 않는다. 업종 가족 24채는 문형이 같아도 문자열이 24개다. "지나침 (만취)"와 "지나침 (포만)"도 문자열이 둘이다.
3. **효과는 데이터로 갖고 문구는 만든다.** 문체를 바꿀 때와 용어를 바꿀 때 모두 데이터는 그대로 두고 100개를 다시 냈다. 다른 언어도 그 언어의 문형에 같은 데이터를 채운다.
4. **특성은 배지다.** 이름과 문법으로 엮이지 않는다.
5. **이름은 하나를 짓고 14개 언어로 옮긴다**(11-24 확정. 사용자: "이름이 달라지면 디자인도 달라져야 한다"). 그림은 하나다. 드워프의 이름은 소리대로 적는다. 원칙과 방법은 `이름짓기_2~4단계_유형_원칙_방법.md`에 있다.
6. **덱의 취향은 라벨과 아이콘이다.**
7. **지금 값의 꼬리는 문자열 하나다.**

## 10. 검증과 남은 것

| 한 것 | 남은 것 |
|---|---|
| 문구를 데이터에서 만들었다. 매장 52곳은 시뮬레이터의 건물 정의에서 읽었다 | 지원 건물 43채의 효과 데이터는 손으로 적었다. 참고 엔진을 2.0으로 올릴 때 대조한다 |

## 11. 한계

- 문구는 아직 사람이 읽어 본 적이 없다. 데모 2.0이 답한다.
- 조작층 문구는 화면 설계 없이 쓴 초안이다.
- 툴팁의 정의는 시뮬레이터의 동작을 옮긴 것이다. 규칙 문서 v3을 쓸 때 다시 맞춘다.
- 특성 "배고픔"과 스택 "허기", 특성 "술기운"과 스택 "취기"는 뜻이 가깝다. 이름 짓기 5차에서 다시 봤고 그대로 두기로 했다(특성의 이름은 주는 스택이 떠올라야 한다. 스택 2를 달고 시작하므로 문턱 3의 키워드보다 약한 말인 것이 맞는다).
- 공원, 수영장, 극장도 "매장"이라고 부른다. 어색한지는 해 보고 판단한다.
