# 욜로드워프 데모 2.0

고리 모양 거리에 건물을 짓고 드워프를 돌려 돈을 버는 로그라이크 타이쿤의 데모.
한 런은 스테이지 다섯(8, 12, 16, 20, 24칸), 웨이브 스물다섯이다.
규칙은 `docs/demo2/욜로드워프_데모2_규칙.md`, 화면의 글은 `docs/demo2/욜로드워프_데모2_텍스트_v3.md`를 따랐다.
데모 1.0(12칸, 웨이브 다섯)은 git 기록에 남아 있다.

## 실행하는 법

[Node.js](https://nodejs.org)(18 이상)만 있으면 된다. 설치할 것은 없다. 이 폴더(`yolodwarf`)에서:

```bash
npm start
```

그다음 브라우저에서 <http://localhost:5173> 을 연다. 끌 때는 터미널에서 Ctrl+C.

## 검증하는 법

```bash
npm test
```

`모두 통과`가 나오면 된다. 넷을 본다.

1. `data/yolodwarf2_testcases.json`의 검증 사례 221개.
2. 받은 참고 엔진(`docs/demo2/reference_engine2.mjs`)과 무작위 보드 2,000개로 맞대기. 화면이 쓰는 기록(계산식, 매출의 합)이 결과와 맞는지도 본다.
3. 제작 요청서 5.2절의 일곱 가지: 후보 뽑기, 덱, 업그레이드, 새로고침, 스테이지 전환, 판정, 웨이브 끝.
4. 무작위로 누르는 봇 60런: 규칙이 지켜지는지, 같은 씨앗이면 같은 판인지, 스테이지 5의 끝까지 가는지.

`node test/bot.mjs 60`은 검증이 아니라 밸런스 참고용이다.

## 수치를 고치는 법

`data/yolodwarf2_data.json`을 고치고 브라우저를 새로고침한다. 코드에는 숫자를 적지 않았다.

- `stages`: 칸 수, 정비마다 짓는 수, 후보 수, 새로고침의 처음 값, 목표 다섯.
- `constants`: 시작 자금, 기본 바퀴, 추가 바퀴의 비용, 문턱, 업그레이드, 후보의 확률, 덱의 무게.
- `shops`, `supports`, `traits`, `dwarves`: 요금, 효과, 문구(`text`), 이름.

수치를 바꾸면 `npm test`의 검증 사례는 어긋나는 것이 정상이다.

## 한 파일로 묶기 (웹에 올릴 때)

```bash
node build-single.mjs
```

`dist/yolodwarf2-single.html` 하나에 화면, 엔진, 데이터가 모두 들어간다. 데이터를 고쳤으면 다시 묶어야 반영된다.

## 조작

- **정비**: 후보를 빈 칸에 끌어다 놓거나, 후보를 누른 뒤 빈 칸을 누른다. 지은 건물을 누르면 오른쪽 살펴보기 창에 `업그레이드`와 `철거`가 나온다. 건물을 끌면(또는 건물, 칸 순서로 누르면) 자리를 바꾼다.
- **웨이브**: 드워프 카드의 `보내기`. 카드에 마우스를 올리면 좋아하는 매장(♥)과 싫어하는 매장(✕)이 보드에 보인다.
- **도는 동안**: `1배 / 2배 / 4배`, `결과만 보기`. `계속 결과만 보기`를 켜면 다음 드워프부터도 건너뛴다.
- **살펴보기**: 건물에 마우스를 올리면 요금과 ×가 어디에서 왔는지 풀어 보여 준다. 지원 건물은 닿는 칸이 초록, 매장은 자기에게 걸린 지원 건물이 하늘색으로 밝혀진다. 👑는 요금이 가장 높은 매장, 🏅는 ★이 가장 많은 매장이다.
- **기록**: 칸, 매장, 계산식, 매출, 스택과 만족도의 변화가 한 줄씩 쌓인다. `크게 / 작게`로 넓힌다.
- **설정**: 시험용 스위치 여섯 개(목표 배율, 시작 스테이지, 예상 매출 미리보기, 특성, 덱의 색, 난수 씨앗).

## 스스로 정한 것

규칙 문서와 참고 엔진에 없어서 가장 단순한 쪽으로 정한 것. 규칙과 수치는 고치지 않았다.

1. **정비가 시작될 때 잠그지 않은 후보는 모두 새로 뽑는다.** 규칙 3.3절의 "잠근 후보가 있으면 그것부터 채운다"를 이렇게 읽었다. 지난 정비에 짓지 않고 남긴 후보는 잠그지 않았으면 사라진다.
2. **철거하고 같은 정비에 다시 지은 건물은 새 건물이다.** ★과 매출 기록이 없고 그 정비에는 올릴 수 없다.
3. **매출 기록은 칸이 아니라 건물에 붙는다.** 웨이브 도중에 자리를 바꿔도 그 건물의 기록에 쌓인다.
4. **시작 스테이지 스위치의 자금**은 앞 스테이지의 마지막 목표에 목표 배율을 곱한 값이다. 목표 배율로 생긴 소수는 올린다.
5. **스위치가 먹는 때.** 예상 매출 미리보기는 바로, 목표 배율과 시작 스테이지와 특성과 덱의 색은 새 런부터다.
6. **난수 씨앗은 글자도 받는다.** 드워프의 덱과 차례는 씨앗과 스테이지, 웨이브로만 정해져서 새로고침을 몇 번 눌렀든 같다. 후보는 새로고침을 누른 횟수에 따라 달라진다.
7. **최고 기록은 최종 자금이다**(텍스트 v3의 `record.run`). 시험용 스위치를 켠 런도 기록되고, 화면 위에 "시험용 스위치 켜짐"이 뜬다. 1.0의 기록과는 따로 저장한다.
8. **"한 번에 올린 최고 매출"은 이용 한 번의 매출이다.** 1.0은 드워프 한 마리의 합이었다.
9. **철거, 새 런, 건설을 남긴 웨이브 시작은 두 번 눌러야 한다.** 브라우저의 확인 창이 막힌 곳이 있어 알림을 띄우고 한 번 더 누르게 했다.
10. **`계속 결과만 보기`를 넣었다.** 요청서에는 없다. 스물다섯 웨이브를 끝까지 하려면 필요해 보였다. 시험용 스위치로 치지 않는다.
11. **조작층 문구.** 텍스트 v3의 8절에 없는 안내(조작 설명, 철거 확인, 건설을 다 썼을 때 들)는 같은 해요체로 채웠다. 8절의 "처음 몇 번"만 뜨는 안내 둘은 늘 보드 가운데에 뜬다.
12. **문구의 `[업종]`은 아이콘과 업종 이름을 함께 그렸다.** 이모지 아이콘만으로는 여덟 업종이 잘 구별되지 않았다. 그림이 생기면 아이콘만 남기면 된다(`ui.js`의 `rich`).
13. **키워드 풀이는 툴팁이 아니라 살펴보기 창의 아래에 붙였다.** 문구에 나온 키워드만 나온다.
14. **피버타임의 속도.** 추가 바퀴 하나마다 35%씩 빨라지고 3배에서 멈춘다(1.0과 같다).
15. **화면 크기.** 가로 1240 이상의 데스크톱 기준이다. 24칸 보드에서는 지원 건물의 문구가 칸에 다 들어가지 않는다. 마우스를 올리면 살펴보기 창에 다 나온다.

## 만들면서 눈에 띈 것

손으로 여러 런을 해 본 것이 아니라 봇과 자동 브라우저로 돌려 보며 본 것이다. 수치는 고치지 않았다.

- **단순한 봇은 스테이지 1의 다섯째 웨이브(목표 3,000)에서 많이 끝난다.** 60런 가운데 26런이 1-5에서, 8런이 그 앞에서 끝났고 클리어는 2런이었다. 이 봇은 예상 매출을 보고 짓고 보내지만 새로고침, 잠금, 자리 바꾸기, 철거는 하지 않는다. 사람은 다를 것이다. 다만 8칸에서 500 → 1,500 → 3,000으로 오르는 구간이 첫 벽으로 보인다.
- **덱의 색은 문서의 숫자대로 나온다.** 덱 300개 평균으로 인기 업종 하나를 좋아하는 드워프가 13.1마리, 비인기 업종을 좋아하는 드워프가 3.0마리, 싫어하는 드워프가 10.1마리다.
- **요금이 0인 공원은 업그레이드 비용이 늘 최소 10이다.** 매출이 0이라서다. 공원을 싸게 ★★★로 올려 건축 사무소(보드의 ★ 1개당 모든 매장 요금 +1)를 키울 수 있다. 명예의 전당의 대상(★이 가장 많은 매장)도 공원이 될 수 있는데, 그러면 ×2가 요금 0에 걸려 헛돈다. 의도인지 확인이 필요하다.
- **스테이지의 첫 웨이브는 거의 판정이 없다.** 앞 스테이지의 마지막 목표와 다음 스테이지의 첫 목표가 100~500밖에 차이 나지 않아서, 새 보드에서 조금만 벌거나 이미 넘은 채로 들어간다. 문서가 말한 대로다.
- **스테이지가 바뀔 때 잃는 것이 크다.** ★★★까지 올린 매장과 보드 전체가 사라진다. 다섯째 웨이브 앞의 업그레이드는 그 웨이브 한 번만 쓰고 버리는 셈이다.
- **4배속의 길이.** 12칸에서 네 바퀴를 도는 드워프 한 마리가 4초쯤이었다. 24칸은 재지 않았다. 칸과 매장이 두 배이므로 한 마리에 8~10초, 한 웨이브에 30초쯤으로 어림한다. 답답하면 `계속 결과만 보기`가 있다.
- **만족도가 0 아래로 내려가는 것이 화면에서 세다.** 싫어하는 매장이 많은 보드에서는 만족도가 음수로 쌓이는 것이 빨갛게 보인다. 드워프를 고를 때 ✕ 표시를 보게 만든다.
