# 욜로드워프 데모 3.0

고리 모양 거리에 건물을 짓고 드워프를 돌려 돈을 버는 로그라이크 타이쿤의 데모.
손패로 건물을 얻고, 같은 매장을 겹쳐 ★을 올리고, 지원 건물이 드워프가 지나갈 때 매장의 배율을 키운다. 특수 칸 8가지와 귀빈 6명이 새로 들었다.
한 런은 웨이브 열이고, 보드는 8칸에서 정비마다 1칸씩 자라 17칸(특수 칸을 끼워 넣으면 19칸까지)이 된다.

- 규칙: `docs/demo3/욜로드워프_데모3_규칙.md`
- 무엇을 어떻게 만들고 확인하는지: `docs/demo3/욜로드워프_데모3_제작요청서.md`
- 묶음의 `욜로드워프_데모3_기획_초안.md`(참고 문서)는 받지 못해 `docs/demo3/`에 없다.

이 판은 `demo3` 브랜치에 있다. 시제품 1차는 `proto1`, 데모 2.0은 `claude/affectionate-noether-6z549y` 브랜치에 그대로 있다.

## 실행하는 법

[Node.js](https://nodejs.org)(18 이상)만 있으면 된다. 설치할 것은 없다. 이 폴더(`yolodwarf`)에서:

```bash
npm start
```

그다음 브라우저에서 <http://localhost:5173> 을 연다. 끌 때는 터미널에서 Ctrl+C.

## 검증하는 법

```bash
npm test
```

`모두 통과`가 나오면 된다. 다섯을 본다.

1. `data/yolodwarf3_testcases.json`의 검증 사례 494개(묶음 열여섯).
2. 받은 참고 엔진(`docs/demo3/reference_engine3.mjs`)과 무작위 보드 2,000개로 맞대기: 웨이브의 계산과 보드에 손대는 일. 화면이 쓰는 기록(계산식, 매출의 합, 걷는 차례, 자란 배율)이 결과와 맞는지, 드워프 한 마리의 계산이 상태를 바꾸지 않는지도 본다.
3. 제작 요청서 8.3절의 열네 가지: 보드, 시작 손패, 후보, 고르기, 손패, 새로고침, 덱, 순서, 쿠폰 가판대, 버스 터미널, 귀빈, 보상, 끼워 넣기, 미리보기.
4. 무작위로 누르는 봇 60런: 규칙이 지켜지는지, 같은 씨앗이면 같은 판인지, 웨이브 10과 19칸까지 가는지, 지원 건물 20채와 특수 칸 8가지가 모두 나오는지.
5. 지원 건물 20채를 하나씩, 그리고 매장, 특수 칸, 귀빈을 몇 개 데이터에서 지우고도 런이 끝까지 도는지.

## 수치와 목록을 고치는 법

`data/yolodwarf3_data.json`을 고치고 브라우저를 새로고침한다. 코드에는 숫자를 적지 않았다.

- `waves`: 칸 수, 목표, 새로고침의 처음 값. `constants`: 손패(후보 수, 고르는 수, 남기는 수), 확률, ★, 귀빈, 문턱.
- `shops`, `supports`, `specialTiles`, `guests`: 수치, 문구, 목록. 건물 하나를 지우면 그 건물 없이 돌아간다.
- 잠깐 끄기만 하려면 게임의 `설정`에서 `건물 끄기`를 쓴다.

수치나 목록을 바꾸면 `npm test`의 검증 사례는 어긋나는 것이 정상이다.

## 조작

- **후보**: `고르기`로 2장까지 손패에 넣는다. 둘째 정비부터 첫 장에는 "지은 매장" 표시가 있다.
- **손패의 카드를 쓴다**: 카드를 끌어다 놓거나, 카드를 누른 뒤 놓을 곳을 누른다.
  - 빈 칸: 짓는다. 같은 이름의 매장: 겹친다(★ +1). 다른 건물: 바꿔 짓는다. 칸과 칸 사이의 틈(●): 끼워 넣는다. `버리기` 자리: 버린다.
  - 놓기 전에 그 자리에서 무슨 일이 일어날지가 뜬다(잃는 ★과 배율 포함).
- **끼워 넣기**: 카드나 보드의 건물을 들면 틈마다 ●이 뜬다. 틈 위에 올리면 밀릴 건물 전부가 움직일 방향으로 반 칸쯤 비켜나고, 놓으면 그대로 밀린다. 미리 보기와 실제 결과는 같은 함수(`game.simulate`, 엔진의 `apply`)에서 나온다.
- **보드의 건물**: 끌어서 다른 칸에 놓으면 자리 바꾸기, 틈에 놓으면 끼워 넣기. 건물을 누르면 오른쪽 살펴보기 창에 `철거`가 나온다. 정비 때와 드워프를 고르기 전에 할 수 있다.
- **특수 칸**: 금빛 줄무늬 칸이다. 칸 아래에 이름이 적혀 있고, 터줏자리에 남은 배율도 거기에 적힌다.
- **귀빈의 보상**: 특수 칸 후보 하나를 누르고, 보드의 틈(●)을 눌러 자리를 고른 뒤 `여기에 끼워 넣기`를 누른다. 누르기 전에는 자리를 바꿔 볼 수 있다.
- **도는 동안**: `1배 / 2배 / 4배`, `결과만 보기`, `계속 결과만 보기`.
- **설정**: 런 시작 화면 아래의 `설정 · 시험용 스위치`. 끝 화면에 `기록 복사`가 있다(복사가 막힌 곳에서는 글상자에 같은 글이 나온다).

## 스스로 정한 것

규칙 문서와 참고 엔진에 없어서 가장 단순한 쪽으로 정한 것. 규칙과 수치는 고치지 않았다.

1. **인기 업종과 비인기 업종(덱의 색)을 뺐다**(사용자 요청). 규칙 문서 4.1절과 제작 요청서 7절에는 있지만 넣지 않았다. 덱은 90마리에서 고르게 30마리를 뽑고 그 가운데 10마리가 특성을 갖는다. `덱의 색` 스위치와 기록 복사의 "덱의 인기 업종" 줄도 없다. 데이터의 `constants.deck.popularKinds`, `unpopularKinds`, `weights`는 그대로 두었지만 쓰지 않는다. 문서의 목표는 덱의 색이 있는 봇으로 잰 값이다.
2. **후보에서 고른 카드는 되돌릴 수 없다.** 2장을 다 고르면 새로고침도 누를 수 없다(다시 뽑아도 고를 수 없어서).
3. **손패에 있는 지원 건물은 후보에 나오지 않는다**(규칙대로). 그래서 `꼭 나오게 하기`로 고른 건물이 시작 손패에 이미 있으면 후보에는 나오지 않는다.
4. **스위치의 세부.** `귀빈 고르기`로 정하지 않은 자리는 남은 귀빈 가운데서 서로 다르게 뽑는다. `시작 특수 칸`은 종류만 정하고 칸은 무작위다. `보상 후보를 늘 셋`은 3, 6웨이브에만 듣는다.
5. **보상은 건너뛸 수 없다.** 후보가 나오면 하나를 골라 끼워 넣어야 다음 정비로 간다.
6. **웨이브의 끝의 일(대기업 사옥, 팝업 스토어)은 판정 바로 뒤에 일어난다.** 판정 화면에서 보드가 이미 바뀌어 있고, 무슨 일이 있었는지는 알림과 기록 창에 나온다. 보상의 화면은 `보상 고르기`를 누른 뒤에 뜬다.
7. **웨이브의 매출은 건물을 따라간다.** 웨이브 도중에 매장을 옮겨도 그 매장에 들어온 매출로 셈한다(대기업 사옥이 본다).
8. **웨이브 도중에 보낼 횟수가 줄면**(버스 터미널을 철거했다) 이미 그만큼 보냈을 때 웨이브가 거기서 끝난다.
9. **특수 칸을 끼워 넣은 정비에도 고리의 끝에 새 칸이 하나 생긴다.** 그래서 보상을 받은 정비에는 칸이 둘 는다.
10. **칸 수가 홀수일 때의 모양.** 네모 트랙은 칸 수가 짝수여야 닫히므로, 홀수일 때는 입구 바로 앞에 빈 자리 하나를 두었다. 규칙의 칸은 아니다.
11. **조작은 끌어다 놓기와 눌러서 고르기를 모두 둔다.** 눌러서 고르면 틈마다 ●이 뜬다.
12. **확인.** 철거와 새 런은 두 번 눌러야 한다. 후보를 덜 고른 채 웨이브를 시작할 때도 한 번 더 묻는다. 손패가 2장을 넘으면 시작되지 않고 안내가 뜬다.
13. **"한 번의 이용에서 올린 최고 매출"에는 귀빈의 ×3이 들어간다.** 최고 기록은 최종 자금이고 데모 3.0만 따로 저장한다.
14. **설정의 확률 표기.** 텍스트 v3이 %를 쓰지 않아서 "30 / 45 / 60 (100장에 몇 장)"으로 적었다.
15. **배율이 가장 높은 매장의 표시(👑)**는 2호점이나 방명록이 보드에 있을 때만 뜬다(요청서대로). 대기업 사옥의 양옆 매장에는 ⚔가 뜬다.
16. **화면 크기.** 가로 1240 이상의 데스크톱 기준이다. 칸이 많아지면 지원 건물의 문구가 칸에 다 들어가지 않는다. 마우스를 올리면 살펴보기 창에 다 나온다.

## 만들면서 눈에 띈 것

손으로 여러 런을 해 본 것이 아니라 테스트와 자동 브라우저로 돌려 보며 본 것이다. 수치는 고치지 않았다. 밸런스용 봇은 따로 돌리지 않았다.

- **귀빈의 보상을 못 받는 일이 흔했다.** 자동으로 돌린 런들에서 귀빈 넷(순례자, 잠꾸러기, 수집가, 미식가)이 모두 추가 바퀴 0번이었다. 생각 없이 지은 보드이긴 하지만, 귀빈이 좋아하는 업종의 매장이 보드에 없으면 특수 칸을 하나도 못 받는다. `보상 후보를 늘 셋` 스위치로 특수 칸을 볼 수 있다.
- **끼워 넣기가 고리를 넘어 밀 때 놀랄 수 있다.** 0번과 1번 사이에 놓았는데 가장 가까운 빈 칸이 뒤쪽이면 0번의 건물이 마지막 칸으로 밀린다(입구의 건물이 바뀐다). 규칙대로이고 미리 보기에 보이지만, 드워프가 도는 차례가 달라지는 이동이다.
- **첫 웨이브의 목표 140이 낮지 않다.** 시작 손패를 받은 순서대로 지은 자동 실행은 첫 웨이브의 매출이 40이었다. 사람이 하면 다를 것이다.
- **덱의 색이 없어서** 문서의 목표(덱의 색이 있는 봇의 가운데 판의 10분의 3)와 조건이 다르다. 어느 쪽으로 쉬워지고 어려워지는지는 재지 않았다.
- **손패가 6장일 때** 카드가 좁아져 문구가 서너 줄로 접힌다. 읽을 수는 있다.
