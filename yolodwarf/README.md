# 욜로드워프 데모

고리 모양 보드에 가게를 짓고 드워프를 돌려 돈을 버는 로그라이크 타이쿤의 기획 검증용 데모.
한 판은 스테이지 하나, 웨이브 다섯이다. 규칙은 `docs/욜로드워프_데모_제작요청서.md`를 그대로 따랐다.

## 실행하는 법

[Node.js](https://nodejs.org)(18 이상)만 있으면 된다. 설치할 것은 없다. 이 폴더(`yolodwarf`)에서:

```bash
npm start
```

그다음 브라우저에서 <http://localhost:5173> 을 연다. 끌 때는 터미널에서 Ctrl+C.

(Node 대신 파이썬이 있다면 `python3 -m http.server 5173`도 된다. `index.html`을 더블클릭해서 여는 것은 브라우저가 막는다.)

## 검증하는 법

```bash
npm test
```

`모두 통과`가 나오면 된다. 세 가지를 본다.

1. `data/yolodwarf_testcases.json`의 사례 136개(singleRuns 128 + waves 8) 전부.
2. 요청서 9.2절의 손 계산(칸마다 낸 돈, 만족도, 계산식 글자, 새로고침 값).
3. 진행 규칙: 무작위로 누르는 봇 300판으로 건설 2채 제한, 새로고침 값, 얼리기, 지원 중복 금지, 같은 시드면 같은 판인지 확인.

어긋나면 어느 사례가 어떻게 다른지 한 줄씩 나온다.

`node test/bot.mjs 200`은 검증이 아니라 밸런스 참고용이다. 예상 수입을 보고 두는 단순한 봇이 어디까지 가는지 보여 준다.

## 숫자를 고치는 법

`data/yolodwarf_data.json`을 메모장 같은 편집기로 고치고 저장한 뒤 브라우저를 새로고침한다.

- `config`: 목표(`targets`), 시작 돈, 건설 횟수, 새로고침 비율, 한 바퀴 값, 만취·배부름 문턱 등.
- `buildings`: 요금(`fee`), 효과 값, 나올 무게(`weight`), 효과 글귀(`text`).
- `dwarves`: 좋아하는 종류, 싫어하는 종류.

숫자를 바꾸면 `npm test`의 검증 사례는 어긋나는 것이 정상이다(사례는 원래 숫자로 만든 것이다).
쉼표나 따옴표가 깨지면 화면에 "데이터 파일을 읽지 못했습니다"가 뜬다.

## 조작

- **정비**: 후보를 빈 칸에 끌어다 놓거나, 후보를 누른 뒤 빈 칸을 누른다. 보드의 건물은 끌어서(또는 건물, 칸 순서로 눌러서) 자리를 바꾼다.
- **웨이브**: 드워프 카드의 `보내기`. 카드에 마우스를 올리면 좋아하는 건물(♥)과 싫어하는 건물(✕)이 보드에 표시된다.
- **살펴보기**(오른쪽 위): 건물에 마우스를 올리면 요금·곱·한 번 더가 어디에서 왔는지 풀어서 보여 준다. 지원 건물은 닿는 칸이 초록 테두리로, 장사 건물은 자기에게 걸린 지원이 하늘색 테두리로 표시된다.
- **기록**(오른쪽 아래): 칸, 건물, 계산식, 낸 돈, 스택과 만족도의 변화가 한 줄씩 쌓인다.
- **설정**: 예상 수입 미리보기, 싫어하는 종류 끄기, 시드 넣기. 시드는 화면 오른쪽 위에 늘 보이고 주소에도 붙는다(`?seed=ABC123`).

## 구조

| 파일 | 내용 |
|---|---|
| `js/engine.js` | 계산 엔진(5.5~5.8절). 보드와 드워프를 받아 "어느 칸에서 얼마를 왜 냈는지"의 기록을 돌려주는 순수 함수. 화면도 무작위도 모른다 |
| `js/game.js` | 한 판의 진행(5.1, 5.9~5.11절): 정비, 후보 뽑기, 새로고침, 웨이브, 판정. 화면을 모른다 |
| `js/rng.js` | 시드로 다시 만들 수 있는 무작위 |
| `js/ui.js`, `css/style.css` | 화면. 엔진의 기록을 재생만 한다 |
| `data/` | 데이터 파일과 검증 사례 |
| `test/all.test.mjs` | 검증 |
| `docs/` | 제작 요청서, 받은 참고 엔진 원본 |

규칙을 바꿀 때는 `engine.js`(계산)나 `game.js`(진행)만 고치면 된다. 넣지 않기로 한 것(업그레이드, 아이템, 스테이지 여러 개, 철거 등)을 붙일 자리는 `game.js`의 상태와 단계(`phase`)다.

## 정해야 할 것

문서에 없거나 두 가지로 읽혀서 임시로 정한 것. 규칙과 숫자는 바꾸지 않았다.

1. **다음 정비에 얼리지 않은 후보가 남는가.** 5.9절은 "정비가 시작되면 비어 있는 후보 칸을 채운다"고도 하고 "얼린 후보는 … 다음 정비에도 남는다"고도 한다. 뒤 문장을 따라 **얼리지 않은 후보는 다음 정비에 모두 새로 뽑는다**로 했다. 그러지 않으면 얼리기가 새로고침을 누를 때만 뜻이 있다. 바꾸려면 `game.js`의 `enterPrep` 한 줄이다.
2. **새로고침으로 사라지는 지원이 그 새로고침에 다시 나올 수 있는가.** 나올 수 있게 했다. 풀에서 빼는 것은 보드의 지원, 얼린 후보의 지원, 같은 뽑기에서 먼저 나온 지원이다.
3. **시드가 정하는 범위.** 후보와 드워프는 서로 다른 수열을 쓴다. 드워프 순서는 시드와 웨이브 번호만으로 정해져서, 새로고침을 몇 번 눌렀든 같은 시드면 같은 드워프가 나온다. 후보는 새로고침을 누른 횟수에 따라 달라진다.
4. **2호점에 변전소가 붙었을 때 첫 이용이 거절되면** 남은 이용도 하지 않는다(받은 참고 엔진과 같다). 문서의 "남은 한 번 더도 하지 않는다"를 2호점에도 적용한 것이다.
5. **시험용 스위치를 켠 판의 기록.** 예상 수입을 켜거나 싫어하는 종류를 끈 판도 역대 최고에 그대로 기록된다. 화면 위에 "시험용 스위치 켜짐"이 뜬다. 스위치는 판 도중에 바꿀 수 있고 다음 보내기부터 적용된다.
6. **성장 표시의 말.** 축제 본부와 방송국이 키우는 값을 타일에는 문서의 말대로 "배수 +0.5"로 적고, 바퀴가 끝날 때 뜨는 알림에는 실제로 늘어난 곱(예: 곱 4인 건물이면 "곱 +2")을 적었다.
7. **건설을 남기고 웨이브를 시작하면** 확인 창을 한 번 띄운다. 실수 방지용이다.
8. **피버타임의 속도.** 추가 바퀴 하나마다 35%씩 빨라지고 3배에서 멈춘다. 숫자는 `ui.js`의 `wait`에 있다.
9. **화면 크기.** 가로 1280 이상의 데스크톱 기준이다.

## 만들면서 눈에 띈 것

직접 손으로 여러 판을 해 본 것이 아니라, 봇과 자동 브라우저로 돌려 보며 본 것이다. 기획자가 해 볼 때 확인할 거리로 적는다.

**규칙에서**

- **첫 웨이브가 후보 운에 크게 달렸다.** 시작 돈 10으로 새로고침은 두 번(3, 6)이 끝이다. 봇 200판 가운데 5판은 첫 웨이브에서 끝났다. 후보 5장이 지원 위주로 나오면 손쓸 것이 없다. 의도한 "허무한 판"인지 확인이 필요하다.
- **단순한 봇의 클리어는 200판 가운데 42판(21%)이었다.** 통과한 웨이브 수 분포는 0~5가 5 / 28 / 45 / 50 / 30 / 42. 이 봇은 예상 수입을 보고 드워프를 고르지만 새로고침, 얼리기, 자리 바꾸기는 하지 않는다. 판마다 최고 수입의 중앙값은 372, 상위 10%는 1,778, 최고는 3,488이었다.
- **자리 바꾸기가 무료·무제한이고 보내기 전에도 된다.** 만족도가 0 아래로 안 내려가므로, 드워프마다 싫어하는 건물을 입구 쪽으로 옮기는 것이 늘 이득이다. 보낼 때마다 보드를 다시 짜는 것이 정답이 되어 번거로울 수 있다.
- **성장 지원은 세 번째 드워프에게 몰린다.** g가 이어지므로 오래 도는 드워프를 먼저 보내 g를 쌓고 마지막에 터뜨리는 순서 고민이 생긴다. 2번 질문(누구를 보낼까)에는 좋은 재료로 보인다.
- **선술집 하나가 뒤의 수영장·헬스장·극장을 모두 막는다.** 만취 문턱 3을 한 번에 채우기 때문이다. 순서 퍼즐로는 분명하지만 처음에는 왜 수입이 0인지 놀랄 수 있다. 화면에 거절 이유가 뜨고 기록에 남는다.
- **취향은 낸 돈과 무관하다.** 예상 수입을 끄면 드워프를 고르는 근거가 사실상 "좋아하는 건물이 몇 채인가"(바퀴 수)뿐이다. 살펴보기 창에 그 수를 적어 두었다.

**화면에서**

- **1배속이 길다.** 건물 열 채 보드에서 네 바퀴를 도는 드워프 한 마리가 20~30초쯤 걸린다. 웨이브 하나에 1분 남짓이다. 후반에는 2배속이 기본이 될 것 같다.
- **4배속에서는 계산식을 읽을 수 없다.** 숫자가 튀는 느낌만 남는다. 식을 확인하려면 기록 창을 본다.
- **"한 번 더"와 2호점은 같은 칸에 알림이 연달아 뜬다.** 겹치지 않게 조금씩 올려 띄웠지만 세 번을 넘으면 다시 겹친다.
- **"요금이 가장 높은 건물"이 바뀌는 순간이 조용하다.** 자리 바꾸기나 건설로 ★가 옮겨 가도 따로 알리지 않는다. 관광 안내소·방송국·2호점을 쓰는 판에서는 놓치기 쉽다.
- **건너뛰면 알림이 한꺼번에 뜬다.** 결과는 같고 기록 창에는 모두 남는다.
