# 욜로드워프 시제품 1차

건물을 다시 기획하려고 만든 시제품 판. 지원 건물 시제품 24채(와 랜드마크)를 해 보고 살릴지, 고칠지, 버릴지를 정하는 데 쓴다.
한 런은 웨이브 열이고, 보드는 8칸에서 시작해 웨이브마다 2칸씩 자라 26칸이 된다.

- 바뀐 규칙과 건물마다의 동작: `docs/proto1/욜로드워프_시제품1_제작요청서.md`
- 건물마다 무엇을 보려는지: `docs/proto1/건물기획_시제품_1차.md`
- 바탕 규칙과 글: `docs/demo2/`의 규칙 문서 v3과 텍스트 v3

이 판은 `proto1` 브랜치에 있다. 데모 2.0은 `claude/affectionate-noether-6z549y` 브랜치에 그대로 있다.

## 실행하는 법

[Node.js](https://nodejs.org)(18 이상)만 있으면 된다. 설치할 것은 없다. 이 폴더(`yolodwarf`)에서:

```bash
npm start
```

그다음 브라우저에서 <http://localhost:5173> 을 연다. 끌 때는 터미널에서 Ctrl+C.

## 검증하는 법

```bash
npm test
```

`모두 통과`가 나오면 된다. 다섯을 본다.

1. `data/yolodwarf_proto1_testcases.json`의 검증 사례 304개(웨이브의 계산, 웨이브가 끝날 때, 정비를 시작할 때).
2. 받은 참고 엔진(`docs/proto1/reference_engine_proto1.mjs`)과 무작위 보드 2,000개로 맞대기. 화면이 쓰는 기록(계산식, 매출의 합, 걷는 차례)이 결과와 맞는지도 본다.
3. 제작 요청서 8.2절의 열네 가지: 보드, 후보, 새로고침, 덱, 순서, 쿠폰 가판대, 버스 터미널, 철거 업체, 팝업 스토어와 공사 현장, 대출 창구, 잡지사, 이벤트 부스, 팁.
4. 무작위로 누르는 봇 60런: 규칙이 지켜지는지, 같은 씨앗이면 같은 판인지, 웨이브 10과 26칸까지 가는지, 지원 건물 30채가 모두 지어지는지.
5. 지원 건물 31채를 하나씩 데이터에서 지우고도 런이 끝까지 도는지.

## 건물을 끄고, 빼고, 고치는 법

- **잠깐 끄기**: 게임의 `설정`에서 `건물 끄기`의 체크를 푼다. 다음 런부터 후보에 나오지 않는다. 설정은 다음 판에도 남는다.
- **보고 싶은 건물**: `설정`의 `꼭 나오게 하기`에서 셋까지 고른다. 첫 정비의 후보에 들어간다.
- **아예 빼기**: `data/yolodwarf_proto1_data.json`의 `supports`에서 그 건물을 지우고 새로고침한다. 그 건물 없이 돌아간다.
- **수치 고치기**: 같은 파일에서 고친다. `waves`(칸 수, 목표, 새로고침의 처음 값), `constants`(짓는 수, 후보 수, 확률 들), 건물마다의 `effect`와 `text`. 코드에는 숫자를 적지 않았다.

수치나 목록을 바꾸면 `npm test`의 검증 사례는 어긋나는 것이 정상이다.

## 기록 복사

끝 화면(클리어했을 때와 떨어졌을 때 모두)의 `기록 복사`를 누르면 그 판의 기록이 글로 클립보드에 들어간다. 난수 씨앗, 켜 둔 스위치, 끈 건물, 덱의 색, 웨이브마다의 목표와 매출과 자금, 후보에 나온 지원 건물, 지은 건물, 철거한 건물, 업그레이드한 매장, 마지막 보드, 최종 자금이 들어 있다. 복사가 막힌 곳에서는 같은 글이 끝 화면의 글상자에 나오므로 거기서 골라 복사한다.

## 한 파일로 묶기 (웹에 올릴 때)

```bash
node build-single.mjs
```

`dist/yolodwarf-proto1-single.html` 하나에 화면, 엔진, 데이터가 모두 들어간다. 데이터를 고쳤으면 다시 묶어야 반영된다.

## 조작

- **정비**: 후보를 빈 칸에 끌어다 놓거나, 후보를 누른 뒤 빈 칸을 누른다. 지은 건물을 누르면 오른쪽 살펴보기 창에 `업그레이드`와 `철거`가 나온다. 건물을 끌면 자리를 바꾼다.
- **웨이브**: 드워프 카드의 `보내기`. 카드에 마우스를 올리면 좋아하는 매장(♥), 싫어하는 매장(✕), VIP 라운지 때문에 지나칠 매장(🚫)이 보드에 보인다.
- **도는 동안**: `1배 / 2배 / 4배`, `결과만 보기`, `계속 결과만 보기`.
- **표시**: 👑 요금이 가장 높은 매장, ⚔ 대기업 사옥의 양옆 매장, 🎩 VIP 라운지 옆의 매장, ⏳ 팝업 스토어와 공사 현장의 남은 횟수.

## 구조

| 파일 | 내용 |
|---|---|
| `js/engine.js` | 계산 엔진. 보드를 읽고(`prep`), 드워프를 돌리고(`runDwarf`), 웨이브가 끝날 때(`endWave`)와 정비를 시작할 때(`startPrep`) 보드에 일어나는 일 |
| `js/game.js` | 한 런의 진행: 웨이브 열, 보드의 성장, 후보, 덱, 유행, 쿠폰 가판대, 버스 터미널, 철거 업체, 대출 창구, 판정과 순서 |
| `js/rng.js` | 씨앗으로 다시 만들 수 있는 난수 |
| `js/ui.js`, `css/style.css` | 화면. 엔진의 기록을 재생만 한다 |
| `data/` | 데이터 파일과 검증 사례 |
| `test/all.test.mjs` | 검증 |
| `docs/proto1/`, `docs/demo2/` | 시제품 1차 묶음, 데모 2.0의 문서 |

건물은 코드에서 이름이 아니라 데이터의 `effect.type`으로만 가린다. 둘째 묶음에서 건물이 바뀌면 데이터 파일을 갈고, 새 `type`이 생긴 것만 `engine.js`(웨이브의 계산)나 `game.js`(정비와 흐름)에 더하면 된다.

## 스스로 정한 것

제작 요청서와 참고 엔진에 없어서 가장 단순한 쪽으로 정한 것. 규칙과 수치는 고치지 않았다.

1. **정비가 시작될 때 잠그지 않은 후보는 모두 새로 뽑는다**(2.0과 같다). 짓지 않고 남긴 후보는 잠그지 않았으면 사라진다.
2. **웨이브가 끝날 때의 일(3.6절의 3~6)은 판정 바로 뒤에 일어난다.** 판정 화면에서 보드가 이미 바뀌어 있다(대기업 사옥의 철거, 팝업 스토어가 사라짐, 랜드마크). 무슨 일이 있었는지는 알림과 오른쪽 위 창, 기록 창에 나온다.
3. **대출 창구를 다시 지으면 "지금 목표"만큼 빌린다.** 지금 목표에는 먼저 빌린 돈이 들어 있다. 첫 웨이브에서 두 번 지으면 70을 빌리고 그다음에 140을 빌려 빌린 돈이 210이 된다.
4. **플레이어가 철거한 건물의 남은 값은 사라진다.** 팝업 스토어와 공사 현장을 철거하고 다시 지으면 남은 횟수가 처음부터다. 이벤트 부스는 요청서대로 세기가 0이 된다.
5. **쿠폰 가판대와 버스 터미널이 보는 때.** 버스 터미널은 웨이브를 시작할 때 보드에 있는지를, 쿠폰 가판대는 드워프를 보낸 뒤에 보드에 있는지를 본다. 웨이브 도중에는 짓거나 철거할 수 없어서 둘은 같다. 다시 나온 드워프는 셋의 첫 자리에 놓인다.
6. **철거 업체는 철거하는 그때 보드에 있어야 한다.** 철거 업체를 먼저 철거하면 그 뒤의 철거에는 돈이 들어오지 않는다. 철거 버튼에 얻을 금액을 적었다.
7. **꼭 나오게 하기.** 고른 건물은 첫 정비의 후보에서 앞자리를 차지한다. 끈 건물은 고를 수 없다. 공사 현장도 고를 수 있다.
8. **후보 카드의 "(지금 …)".** 후보일 때는 지으면 시작할 값이다(팝업 스토어 2번 남음, 공사 현장 3번 남음, 이벤트 부스 0번째). 거리 표지판은 지금 보드에서 정해질 업종, 잡지사는 이번 웨이브의 유행이다.
9. **유행 표시.** 잡지사가 보드나 후보에 있을 때만 오른쪽 위 창에 "이번 웨이브의 유행"이 뜬다.
10. **이벤트 부스의 "지금 n번째"는 세기를 5로 나눈 나머지다.** 5번째가 터진 직후에는 0번째로 보인다. 4번째일 때 다음 이용이 ×5다.
11. **미리보기의 팁.** "예상 매출 1,234 · 팁 56"처럼 따로 적는다.
0. **인기 업종과 비인기 업종을 뺐다**(11-25 요청). 덱은 90마리에서 고르게 30마리를 뽑고, 그 가운데 10마리가 특성을 갖는다. 화면의 인기·비인기 표시와 `덱의 색` 스위치, 기록 복사의 덱 줄도 없다. 데이터의 `constants.deck.popularKinds`, `unpopularKinds`, `weights`는 그대로 두었지만 쓰지 않는다.
12. **씨앗이 정하는 것.** 덱, 유행, 웨이브마다 나오는 드워프의 차례는 씨앗만으로 정해진다. 후보는 씨앗과 스위치(끈 건물, 꼭 나오게 하기, 확률)와 새로고침을 누른 횟수에 따라 달라진다.
13. **설정을 바꾸는 때.** 런을 시작하기 전(런 시작 화면)에 설정을 열고 닫으면 바꾼 스위치로 런을 다시 짠다. 런 도중에 바꾼 스위치는 예상 매출 미리보기만 바로 먹고 나머지는 새 런부터다.
14. **설정의 확률 표기.** 텍스트 v3이 %를 쓰지 않아서 "30 / 45 / 60 (100장에 몇 장)"으로 적었다.
15. **최고 기록은 최종 자금(빌린 돈을 뺀 값)이고 시제품 판만 따로 저장한다.** 시험용 스위치를 켠 런도 기록되고, 화면 위에 "시험용 스위치 켜짐"이 뜬다.
16. **기록 복사가 막힌 곳**에서는 끝 화면에 같은 글이 든 글상자를 띄운다.
17. **철거, 새 런, 건설을 남긴 웨이브 시작은 두 번 눌러야 한다**(2.0과 같다).

## 만들면서 눈에 띈 것

손으로 여러 런을 해 본 것이 아니라 테스트와 자동 브라우저로 돌려 보며 본 것이다. 수치는 고치지 않았다. 밸런스용 봇은 이 판에서는 따로 돌리지 않았다(묶음의 기획 문서 6절에 봇의 숫자가 있다).

- **팁은 판정 전에 자금에 들어온다.** 요청서의 순서(3.6절의 1과 2)대로다. 그래서 팁 상자는 목표를 넘기는 데에도 쓰인다.
- **대출 창구는 지었다 헐고 다시 짓는 것이 된다.** 헐어도 목표가 내려가지 않으니 이득은 없지만, 자금이 크게 보여서 은행과 묶으면 이자가 커진다(기획 문서도 적어 둔 것). 빌린 돈이 화면 위에 따로 보인다.
- **회전교차로를 0~2번 칸에 두면 돌아갈 칸이 모자란다.** 입구 앞으로 넘어가지 않아서다. 건물에 마우스를 올리면 돌아갈 칸이 밝혀진다.
- **대기업 사옥은 조용히 큰 일을 한다.** 웨이브가 끝나면 매장 하나가 사라진다. 정비 때 양옆 매장에 ⚔ 표시를 하고 끝날 때 알림을 띄우지만, 어느 쪽이 헐릴지는 웨이브가 끝나야 정해진다.
- **VIP 라운지 옆 휴식의 매장은 아무도 이용하지 않는다**(기획 문서대로). 드워프 카드에 마우스를 올리면 지나칠 매장에 🚫가 뜬다.
- **26칸 보드는 가로 8칸, 세로 7칸이다.** 칸이 좁아서 지원 건물의 문구가 다 들어가지 않는다. 마우스를 올리면 살펴보기 창에 다 나온다.
- **지원 건물은 고르게 나온다.** 후보 56,000장에서 30채가 한 채에 777~890장씩 나왔다.
